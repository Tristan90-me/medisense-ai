MediSense AI

The Problem

People self-diagnose from search results — with no structure and no safety net

A search engine returns pages, not a conversation. It doesn't ask follow-up questions, doesn't flag genuine emergencies consistently, and leaves no record for the next visit or the next doctor. The result: delayed care for real problems, and needless anxiety over harmless ones.

🔍

🚨

📉

No continuity

No record of symptoms, history, or family health context.

The Solution

MediSense AI structures the conversation — it doesn't replace the doctor

A guided, conversational symptom checker that asks the right follow-up questions, cross-checks its own output against a rule-based safety layer and an independent ML model, and keeps a running health record for the whole family.

System Architecture

A conventional MERN stack, deliberately — the innovation is in the diagnostic layer, not the plumbing

Frontend

  • React 19 + Vite — component tree, routing via React Router v7
  • Tailwind CSS v4 + shadcn/ui (Radix) — design-token driven UI
  • Framer Motion — page transitions & micro-interactions
  • Zustand — auth/session state with persistence
  • Leaflet + OpenStreetMap — Care Finder map

Backend

  • Express 5 REST API + JWT auth
  • MongoDB Atlas / Mongoose — sessions, profiles, dependents
  • Google Gemini API — conversational triage + photo analysis
  • GridFS — symptom photo storage
  • Hand-trained Naive Bayes classifier — no external ML service
The Core Differentiator

One assessment, three independent signals

Instead of trusting a single model's guess, every check-in is evaluated three separate ways — and shown to the user side-by-side, not blended into one opaque score.

🧠Signal 1

Gemini LLM

Conversational triage — asks follow-ups, explains reasoning in plain language.

🛡️Signal 2

Rule-Based Triage

Deterministic red-flag checks — a fixed safety net the LLM can't accidentally soften.

📊Signal 3

ML Classifier

From-scratch Naive Bayes model — a fully explainable second opinion, not a black box.

Signal 1 · Conversational Triage

Gemini guides the conversation, not just answers it

A bracket-tagged protocol ([EMERGENCY], [SEVERITY], [SYMPTOMS], [DIAGNOSIS], [SUGGESTIONS]) keeps the model's output structured and parseable, streamed to the UI over Server-Sent Events so responses feel immediate rather than a static form.

Low severity Moderate High Critical / emergency
Signal 2 · Rule-Based Safety Layer

A fixed safety net the LLM can't talk itself out of

LLMs are probabilistic — phrasing alone can change how urgently a symptom gets treated. A deterministic keyword/pattern layer runs alongside the model on every message, so a genuine red-flag combination (e.g. chest pain + shortness of breath) is flagged consistently, every time, independent of how the user happened to phrase it.

Why it matters for a defense panel: this is the one place correctness can't be "mostly right" — it's checked by code, not inferred by a model.

Signal 3 · ML Classifier

A hand-trained, fully explainable second opinion

A Bernoulli Naive Bayes classifier, trained from scratch in pure JavaScript — no external ML service, no opaque neural net. Every prediction can be traced back to which symptoms drove it.

Feature · Symptom Photo Log

Some symptoms are easier to show than describe

Photos are stored in MongoDB GridFS and analyzed by Gemini's vision capability, letting a user log a rash, swelling, or visible change over time and get an AI read on it — appended to the same session record as their conversational check-in, not a separate disconnected tool.

Feature · Care Finder

From "you should see someone" to "here's who's nearby"

Built on Leaflet + OpenStreetMap with live queries against the Overpass API — no paid maps API key required. A triage result that recommends care doesn't dead-end in advice; it hands the user an actual next step.

Limitations — Stated Plainly

What this system is not

—

Not a diagnosis. Every assessment is framed as guidance, with an explicit "I'm an AI, not a doctor" disclosure — never buried in a footer.

—

The ML classifier trains on synthetic data. 300 generated records per condition from hand-curated symptom profiles, not real patient records — a deliberate, disclosed trade-off given no clinical dataset was available.

—

Symptom matching is keyword/substring-based for the rule engine and classifier, not full clinical NLP — it can miss symptoms phrased in unusual ways.

—

English-only in the current build.
